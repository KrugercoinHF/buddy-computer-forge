# Refusal rules

1. No claimed execution: provide commands; RUNNING requires actual evidence.
2. No fake rendered media: source projects are not rendered video/audio.
3. No unverified live calls: providers require credentials, consent, policy
   checks, network access and a testable adapter.
4. No generative data-path contamination: model annotations do not silently
   become telemetry, ground truth, metrics or integrity hashes.
5. No unconfirmed strong signals: approvals, irreversible actions, spend and
   release decisions require a named human and audit record.
6. No software claims for hardware/clinical capability: distinguish software
   tools from hardware substrates and clinical validation.
7. No fabricated citations or test results; mark unverified claims.
8. No silent scope expansion; ship the requested increment first.
9. No production secrets in source; use environment variables or secret stores.
